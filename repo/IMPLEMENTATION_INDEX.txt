SECTION 1: CASINO MOCK SERVICE
================================================================================

The Casino Mock simulates a real casino backend, providing wallet operations,
KYC verification, limits checking, and responsible gaming features.

PRIMARY ROUTES:
---------------
1. src/routes/walletRoutes.ts
   - POST /wallet/debit - Deduct funds from player wallet
   - POST /wallet/credit - Add funds to player wallet
   - GET /wallet/balance/:playerId - Get current balance
   - Implements idempotency via IdempotencyStore

2. src/routes/limitsRoutes.ts
   - POST /limits/check - Verify player betting limits
   - GET /limits/:playerId - Get player's current limits
   - Handles jurisdiction-specific limits

3. src/routes/kycRoutes.ts  
   - GET /kyc/:playerId - Get KYC status
   - POST /kyc/verify - Trigger KYC verification
   - Manages KYC states: pending, approved, rejected

4. src/routes/rgRoutes.ts
   - Responsible Gaming endpoints
   - Reality check management
   - Self-exclusion handling

SERVICES:
---------
5. src/services/WalletService.ts
   - Core wallet operations logic
   - Balance management
   - Transaction history
   - Currency handling (EUR)

6. src/services/LimitsService.ts
   - Betting limits enforcement
   - Jurisdiction-specific rules (MGA, UKGC)
   - Max bet/win calculations

7. src/services/KYCService.ts
   - KYC verification logic
   - Status management
   - Integration with external KYC providers (mocked)

8. src/services/ResponsibleGamingService.ts
   - Reality check enforcement
   - Session time tracking
   - Self-exclusion management
   - Cool-off periods

9. src/services/CasinoClient.ts
   - Client for making outbound casino requests
   - Used by other services needing casino integration

TESTS:

   - POST /rgs/api/v1/transaction/credit - Process credit transaction

SECTION 3: ORCHESTRATOR SERVICE
================================================================================

The Orchestrator manages room allocation, player assignment, and coordinates
between Frontend, Backend Game, RGS, and Casino services.

PRIMARY ROUTES:
---------------
1. src/routes/orchestratorRoutes.ts
   IMPLEMENTED (but not conforming to bible):
   - GET /health - Health check
   - POST /health - Method discipline (405)
   - POST /probe/round - Development testing endpoint
   - POST /rooms/allocate - Room allocation
   - GET /rooms/state - Get all rooms state
   - POST /rooms/join - Join a room
   - POST /rooms/leave - Leave a room
   - POST /rooms/close - Close a room
   - POST /match/create - Create match (SHOULD BE IN GAME BACKEND)
   - POST /match/join - Join match (SHOULD BE IN GAME BACKEND)
   - POST /match/start - Start match (SHOULD BE IN GAME BACKEND)
   - GET /openapi.json - OpenAPI spec (dev only)
   - POST /openapi.json - Method discipline (405)

   MISSING (required by bible):
   - POST /assign - Main player assignment endpoint
   - GET /rooms - Room list/health
   - POST /rooms - Create room
   - DELETE /rooms/{roomId} - Drain & terminate room
